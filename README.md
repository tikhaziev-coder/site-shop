# СКС Маркет — демонстрационный интернет-магазин

**Демо-сайт:** https://tikhaziev-coder.github.io/site-shop/

Интерактивный прототип для обсуждения интерфейса и бизнес-сценариев. Не действующий магазин: товары, остатки, цены, адреса и статусы вымышлены. Заказы никуда не отправляются, деньги не списываются, реальная идентификация личности не выполняется. Не вводите реальные паспортные, контактные или платёжные данные.

## Возможности

- Две витрины: украшения и техника; категории, поиск, фильтры, баннеры, предпросмотр и избранное.
- 23 демонстрационных экземпляра, модели техники и отдельные склады золота/техники в подразделениях.
- Общая корзина с группировкой по продавцу и складу; самовывоз или условная доставка.
- Пошаговое оформление: демо-вход, получение, способ оплаты, паспортная анкета по порогу, подтверждение.
- Наличные, карта при получении, онлайн-карта и СБП; имитация успеха, отказа, отмены и повторной оплаты.
- Кабинет, локальные заказы и брони, отмена резерва; оценка вещи и запись в отделение.
- Адаптивный интерфейс для компьютеров, планшетов и телефонов.

## Как проверить оформление

1. Добавьте товары в корзину и перейдите к оформлению.
2. Нажмите «Получить демо-код» и введите **1234**. SMS не отправляется.
3. Выберите получение и оплату. При доставке доступны онлайн-методы.
4. Для проверки анкеты добавьте колье `/p/g09` стоимостью 420 000 ₽. Нажмите «Заполнить пример» вместо ввода реальных данных.
5. Пройдите подтверждение; для онлайн-методов выберите результат тестового платежа.

В этой версии задано согласованное бизнес-правило: анкета требуется **от 60 000 ₽ наличными / от 400 000 ₽ безналично включительно**, только по сумме золота. Техника и доставка в порог не входят; смешанная корзина использует то же правило. Вход нужен для любой покупки. Порог и категория идентификации выделены в коде, а не выводятся из названия витрины.

Это настройка демонстрации, не юридическое заключение. До реального запуска нужны согласование требований идентификации и категорий товаров, серверная авторизация, платёжная интеграция, защищённая обработка персональных данных и проверка цен/остатков на сервере.

## Данные и ограничения

Корзина, избранное, демо-заказы и заявки хранятся только в localStorage конкретного браузера. Признак демо-входа — в sessionStorage. Телефон, паспорт, имя получателя и адрес доставки не передаются и не сохраняются. Паспорт очищается при уходе из оформления, смене оплаты, выходе и завершении заказа. Заполнение анкеты не доказывает личность.

Общих аккаунтов, серверного склада, SMS, реального резерва, эквайринга, СДЭК и интеграции с учётной системой пока нет. У коллег собственные независимые демо-данные. На новом публичном адресе корзина начинается заново: данные с локального адреса автоматически не переносятся.

GitHub Pages здесь используется только для демонстрационного интерфейса, не для продаж или обработки чувствительных данных. Для действующего магазина нужен отдельный подходящий хостинг и backend; см. [ограничения GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

## Запуск и проверки

Требуется Node.js 22+. Рабочих зависимостей у приложения нет.

```sh
npm start
# http://localhost:4173

npm test
npm ci
npx playwright test

npm run build
npm run preview:pages
# http://127.0.0.1:4175/site-shop/
npm run test:pages
```

Браузерные тесты используют установленный Microsoft Edge. Тесты Pages проверяют вложенный путь, прямое открытие и обновление страниц, изображения, оформление и сохранение локальных заказов.

## Публикация

В Settings → Pages выберите GitHub Actions. Workflow `.github/workflows/pages.yml` запускается при push в `main`: модульные тесты → статическая сборка → публикация.

`build.mjs` копирует в `dist/` только разрешённые файлы интерфейса и изображения. Для всех известных маршрутов создаются HTML-оболочки: прямые ссылки и обновление страницы работают без Node-сервера. Неизвестные пути используют `404.html`. Базовый путь — `/site-shop/`; для другого размещения задайте `SITE_BASE` при сборке.

Журналы, зависимости, внутренние документы, локальные инструменты публикации и настройки сети в репозиторий и статическую сборку не включаются. Демо помечено `noindex, nofollow`.

## Структура

- `data.js` — моковые товары, склады, фильтрация и локальный заказ.
- `routes.js`, `navigation.js` — маршруты и размещение в подкаталоге.
- `marketplace.js`, `ui.js` — интерфейс; `state.js` — локальное состояние.
- `payments.js`, `checkout.js`, `checkout.css` — правила и мастер оформления.
- `server.mjs` — локальный сервер; `build.mjs` — статическая сборка.
- `tests/` — модульные и браузерные сценарии.

## Стиль и иллюстрации

Красный #e31e24 и IBM Plex Sans основаны на оформлении [СКС Ломбард](https://sks-lombard.ru/). «СКС Маркет» — рабочее название прототипа. Изображения иллюстративные, характеристики вымышлены: украшения из [Fake Store API](https://fakestoreapi.com/), техника из [DummyJSON](https://dummyjson.com/), часть иллюстраций выполнена в SVG. Авито не парсился. Перед коммерческим использованием необходимы собственные фотографии и проверка прав на все ресурсы.
